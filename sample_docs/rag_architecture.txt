Private Retrieval-Augmented Generation (RAG) Architecture

Retrieval-Augmented Generation (RAG) combines the generative capabilities of language models with private, indexed knowledge sources.

Key Architectural Steps:
1. Ingestion: Raw textual documents (PDF, Markdown, HTML, source code) are loaded and partitioned into semantically cohesive text chunks with sliding-window overlap.
2. Embedding: Text chunks are converted into dense mathematical vectors using local embedding models (such as all-minilm or nomic-embed-text via Ollama).
3. Vector Storage: Dense vectors are indexed using approximate nearest neighbor structures (HNSW) in a persistent vector database (such as ChromaDB) stored in database/.
4. Retrieval: When a user poses a question, the question is transformed into an embedding vector, and cosine similarity is computed to retrieve the top-K most relevant chunks.
5. Grounded Generation: The retrieved passages are injected into an augmented prompt sent to an inference engine (such as Google AI Studio Gemma), guaranteeing that model answers cite factual source data.
